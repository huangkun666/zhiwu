# 数据与恢复

修改笔记、学习数据、原件或备份前，先确定受影响的存储模式和读取入口。

## 数据在哪里

| 使用方式 | 数据位置 | 实现 |
| --- | --- | --- |
| Windows 桌面服务及访问同一服务的手机浏览器或 PWA | `data/zhiwu.db` 存记录，`data/uploads/` 存上传的原件。 | [数据库及启动迁移](../../server/src/db.ts)、[服务路由](../../server/src/index.ts) |
| 安卓独立 APK | IndexedDB 的 `zhiwu_on_device_db`，学习记录和原件随本机状态保存。 | [离线库](../../client/src/api/localEngine.ts)、[API 选择层](../../client/src/api/client.ts) |
| 外部 AI 通过 MCP 收录 | `ZHIWU_URL` 指向的知悟服务库。安卓独立库可通过完整 ZIP 与该库交换记录。 | [MCP 适配器](../../server/mcp.mjs)、[MCP 维护](mcp.md) |

API 选择层在 Capacitor 原生运行或以 `VITE_STANDALONE=true` 构建时选离线实现。设备之间迁移独立库时，在源库导出快照，在目标库预览并合并。

## 笔记、来源和摘录

| 字段 | 用途 |
| --- | --- |
| `content` | 可编辑的 Markdown 正文。照片 OCR 的识别文本也写在这里。 |
| `source_content` | 文件导入提取出的文字，供查找和学习使用，界面在来源区展示。 |
| `source_pages` | PDF 的物理页顺序、每页在 `source_content` 中的 UTF-16 起止位置及提取状态（有文字、无文字、失败）。完整备份及合并会校验它与文字是否匹配。 |
| `attachment_path`、`source_filename` | 原件地址和原文件名。桌面地址通常为 `/uploads/…`，离线库可用内嵌数据地址。恢复时按目标端生成地址。 |
| `chat_excerpts` | 带独立 ID 的聊天摘录。撤销按 ID 删除一条。旧版内联摘录按原块内容和笔记更新时间校验后移除。 |

改正文、导入或撤销时，同时检查 [笔记路由](../../server/src/routes/notes.ts)、[离线实现](../../client/src/api/localEngine.ts)和 [共享内容函数](../../server/src/shared/noteContent.ts)。搜索及生成学习内容要能用正文、提取文本和摘录。桌面的保存、编辑和恢复路径通过 `syncNoteFts` 更新索引。可用的原件从 [来源预览](../../client/src/components/NoteSource.tsx)打开。

助教默认新建普通对话。明确查笔记、续读上一条引用或继续逐段核对时直接检索，明确跳过笔记时只使用最近聊天。其余问题由回答模型直接作答或请求检索；选择查资料时，桌面和安卓才加载允许范围的原文。切换模式后沿用原会话、历史消息和先前保存的参考范围。旧备份缺少模式时沿用深度答疑。规则见[对话处理](../../server/src/shared/tutorConversation.ts)和[会话模式](../../server/src/shared/tutorMode.ts)。

对话可以提出改正文、改名和追加摘录的建议。建议绑定本轮可用笔记的 ID 和版本，改正文还要求原句唯一匹配。点击「应用修改」后，桌面和安卓复用笔记更新接口或按消息 ID 追加摘录。改名、改正文时核对版本；原件、提取文本和其他摘录单独保留。相关规则见[修改建议](../../server/src/shared/tutorNoteEdit.ts)。

三种模式共用[检索与读回流程](../../server/src/shared/tutorContext.ts)，覆盖桌面的一次性回复、流式回复和安卓离线回复。手动勾选限定本轮范围，自动模式只访问可用笔记。短资料可以一次读完。对于长资料，先按标题和段落匹配，再让当前模型查看范围、改用中英文术语、翻查具体页或相邻段落。应用执行每个动作并把结果交还模型，最多六轮。两端均支持普通文本模型返回 JSON 动作。模型未能规划时仍可从本地检索的原文回答。每次读回和回答入库前重新核对来源是否仍可用。

精确查词会遍历限定范围，用引号或型号指出要找的原词时可报告出现次数和位置，较多的位置分批列出。要求找全、总结长文，或文字相似度不足时，可以由当前模型[逐批按含义阅读并摘取引文](../../server/src/shared/tutorScan.ts)。应用校验摘录是否真实存在于所指段落，每次最多八批，在回答中记录核对进度；用户回复“继续”可续读，资料变更后重新核对。该过程会把相应原文批次发给当前配置的模型。最终回答使用带来源编号的原文，资料正文预算约 16,000 字符。

[段落与引用](../../server/src/shared/tutorSources.ts)分别定位笔记正文、导入原文和单条聊天摘录。跳转地址带笔记 ID、来源字段、段号、内容指纹及可用的物理页码。回答只转换本轮实际提供的编号。读回时检查指纹；改动或删除的引用可显示失效提示。模型未标注编号时，单独列出“本轮查阅”。桌面和手机版支持点击引用再返回原对话，保存或恢复会话后仍可打开有效引用。

导入 PDF 时两端逐页提取。打开旧 PDF 或用它答疑时，有原件的旧库可自动补建页索引（包括旧安卓曾截在第 80 页的文本）。缺少原件时继续使用已有文字，只定位到段落。新导入的 Word 表格保留行、列和表头。PDF 无提取文字或提取失败的页单独报告；模型读回指定页时，若具备视觉能力且原件可读，每轮可按需渲染并识别最多两页，识别结果只用于本轮回答和物理页引用。

## 助教历史对话

桌面侧栏和手机「历史对话」使用同一套分页界面。列表每批 30 个会话，以更新时间和会话 ID 倒序排列。按标题、用户问题或助教回答搜索会检查库中的全部会话；多条消息匹配时合并成一个会话结果，并可显示命中的正文片段。查询在当前设备或知悟服务内完成。

继续旧对话时沿用其会话 ID、消息、模式和参考笔记。打开引用后仍可返回原会话。重命名更新原会话的标题和修改时间，完整备份沿用已有的会话和消息结构。确认删除会话会一并移除其中的消息，已单独保存为笔记、摘录或闪卡的内容继续保留。

## 删除和恢复的行为

| 操作 | 保存行为 | 用户可见结果 |
| --- | --- | --- |
| 移入回收站 | 写 `deleted_at` 并更新 `updated_at`，保留 ID、正文、原件及关联。重复移入保持原状态。 | 常规笔记列表、详情、搜索、分类统计和实时笔记引用隐藏该条。由仍可用笔记支持的知识点正常显示。 |
| 恢复 | 清空 `deleted_at`，更新 `updated_at`，沿用原 ID。 | 笔记、原件入口和原有引用重新可见，已有学习记录和排期继续使用。 |
| 永久删除 | 只处理回收站中的笔记，从库中移除记录及索引，清理失效引用。桌面原件仅在库中无其他记录引用时尝试删除。 | 笔记及引用永久移除。测验、聊天、归纳正文、已保存的闪卡和错题等各自保留，缺失的来源链接移除。 |

- 桌面读实时数据用 `active_notes`、`active_concepts` 和 `existingNoteIds`，安卓用 `activeNotes`、`activeConcepts` 和 `noteIdsIn`。修复旧库或永久删除时，`reconcileLibraryReferences` 按仍存在的记录清理引用，其中包括回收站记录。
- 聊天引用的数量和展开列表使用同一组可用笔记。验证移入一篇、全部移入、恢复一篇时的数量和列表。覆盖会话打开期间来源变化及请求乱序返回的情况。
- 学科掌握度由可用笔记关联的已评估概念计算，未评估概念显示为待测。薄弱点判定共用 [todayLearning.ts](../../server/src/shared/todayLearning.ts)。闪卡、错题和已完成测验按自身记录保留，来源移入回收站时仍可继续复习。
- 新生成的测验、闪卡和归纳依赖可用笔记。AI 请求跨越删除时，保存前重新检查来源。测验提交和复习仍按已有记录的规则处理。

相关入口见 [首页统计](../../server/src/routes/dashboard.ts)、[图谱](../../server/src/routes/graph.ts)、[助教会话](../../server/src/routes/tutor.ts)及 [桌面引用修复](../../server/src/db.ts)。

## 完整 ZIP 与合并

[LibraryBackupPanel](../../client/src/components/LibraryBackupPanel.tsx)是产品入口。桌面通过 [备份路由](../../server/src/routes/backups.ts)导出、预览和恢复，安卓用[离线归档适配器](../../client/src/api/backupArchive.ts)。

「设置 → 完整备份」提供「导出完整备份」「选择备份恢复」「局域网快传」。桌面浏览器下载到本机，安卓用系统文件选择器保存。旧 APK 缺少原生保存接口时优先用 WebView 的文件选择器。系统支持分享 ZIP 时，打包后再点「保存或分享 ZIP」选择应用。取消选择可重试。

有些旧版 WebView 提供文件选择器接口，却会在打开窗口前返回 `AbortError`。此时界面提示「备份尚未保存」。可在电脑的「局域网快传」选「接收备份」，手机从同一个快传入口扫码，确认目标电脑，传完在电脑点「下载完整备份」。手机也可用该入口接收电脑发来的文件或同步笔记。更换 APK 前先用「选择备份恢复」打开已保存的 ZIP，核对预览及缺失原件名单。

- ZIP 的 `manifest.json` 由 [libraryBackup.ts](../../server/src/shared/libraryBackup.ts)定义，包含记录快照、原件索引和缺失原件清单。快照覆盖分类、笔记及回收站、聊天、归纳、知识点及关联、测验、闪卡、错题和学习日志。模型凭据和设备设置由各端分别管理。
- 预览读取清单并报告记录、冲突和缺失原件。恢复校验归档及索引要求的附件。导出时已缺失的源文件列入 `missingAttachments`，对应笔记仍可进入备份。旧 JSON 仍可恢复记录及可用的内嵌原件。
- 按记录 ID 合并，通常取较新的记录，时间相同保留目标库版本。更新较新的笔记和复习排期应保留，缺掉的来源字段或原件可以从另一份补齐。旧格式缺少删除标记时保留目标库已有的回收站状态。
- 测验优先保留已完成的一份。相同名称的概念优先沿用库中已有的 ID，按评估次数选进度，同时合并来源并重映射关系。永久删除后若恢复仍含该记录的历史备份，记录按归档内容重新并入。
- 桌面 [backupArchive.ts](../../server/src/services/backupArchive.ts)先暂存附件，再随[快照写入](../../server/src/services/backupSnapshot.ts)提交，失败清理暂存和本次写入的文件。安卓先读出原件再合并并写本机状态。变更格式时同时检查两端归档读取、共享规范化和旧档恢复。

## 恢复验证

1. 用临时库准备一个有层级分类的笔记、一个原文件、一个回收站条目，以及已经完成的测验和一次有排期的复习。
2. 在「设置 → 完整备份」导出 ZIP，到另一端选「选择备份恢复」。先核对预览里的原件、回收站和冲突数量，再确认恢复。
3. 验证分类路径、原件下载、回收站恢复和原有排期。用同一归档重复恢复，检查记录无重复，较新的目标记录仍保留。改归档格式时，再用旧 JSON 和缺少附件的 ZIP 验证。

自动回归入口见 [桌面备份测试](../../server/test/backup.test.mjs)、[离线备份测试](../../client/test/backup.test.mjs)、[桌面笔记测试](../../server/test/notes.test.mjs)和 [离线库测试](../../client/test/library.test.mjs)。
